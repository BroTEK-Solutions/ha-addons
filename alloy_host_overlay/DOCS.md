# Grafana Alloy with Host Processes

This App is the standard Grafana Alloy App with one addition: it can see every
process on the Home Assistant OS host, so a `prometheus.exporter.process`
component (generated here or delivered by Fleet Management) reports the whole
host rather than only the App's own processes. Everything else in this
documentation applies to it unchanged. Install the standard **Grafana Alloy**
App instead unless you need per-process metrics.

## Host process visibility

Home Assistant gives this App the host's process namespace only while its
**Protection mode** is off. Protection mode is the one switch:

- **Protection mode on** (the default after installing): the App runs in its own
  process namespace exactly like the standard Alloy App. Every pipeline works,
  and the log and the Web UI say that host process visibility is not active
  because protection mode is on.
- **Protection mode off**: turn it off on the App's **Info** tab and restart the
  App. The log and the Web UI then say host process visibility is active.

Visibility applies to everything Alloy runs, not to one pipeline. With
protection mode off, every pipeline, whether generated by Local configuration,
delivered by Fleet Management, appended as additional configuration or supplied
as a manual override, can list every host process and its command line. In
Local configuration the **Host process metrics** switch under Metrics only
decides whether the App adds its own generated process pipeline; it is offered
only while visibility is active and needs a Prometheus endpoint.

The generated pipeline keeps cardinality bounded: one series group per
executable name (`{{.Comm}}`), no per-thread series, no smaps-based memory, and
a group disappears when its last process exits. Kernel threads are not counted.
For many processes owned by the host or by other Apps, some per-process files
(such as I/O counters) are not readable, so `namedprocess_scrape_partial_errors`
is non-zero; CPU, memory and process counts are complete.

### The security trade-off

Turning protection mode off is a deliberate security choice. In the host's
process namespace, Alloy, and anything that compromised it, can see every
process on the host, its command line and its resource use. The App asks for
nothing else: no extra capabilities, no full hardware access and no Docker
access. Its AppArmor profile still applies: it may send signals only to its own
processes, it cannot read other processes' environments (where other Apps keep
their Supervisor tokens), and its file-write limits are the same as the
standard App's.

To turn visibility off again, turn **Protection mode** back on and restart the
App. To remove it entirely, uninstall this App and use the standard Alloy App.

### Running beside the standard Alloy App

Both Apps can be installed at once. This App uses its own data directory,
Home Assistant entities, ingress port (8098) and Alloy port (12346), and its
instance name defaults to `homeassistant-host`, so its metrics and its Fleet
Management collector stay separate from the standard App's. Each App leaves out
only its own container's journal by default (`alloy_host` here, `alloy` in the
standard App). Both read the same host journal, so if both send logs to Loki
every entry arrives twice: collect logs in only one of them. If both receive
OTLP traces, enable the trace receiver in only one of them: both listen on
ports 4317 and 4318 of the host network.

Home Assistant rates this App's security lower than the standard App's
(5 instead of 7) because it declares the host process namespace.
